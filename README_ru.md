Программа считает **сезонность по месяцам**: для каждого биржевого инструмента
она определяет, как в среднем менялась его цена в тот или иной календарный месяц
на истории за несколько лет, и собирает результаты в готовый **PDF-отчёт** со
сводной таблицей и детальными помесячными графиками.

Данные берутся **только из локальных файлов** в папке `txt/` — программа ничего
не скачивает и не обращается к сети.

## Как это работает

Программа выполняет три этапа:

| Этап | Модуль | Что делает |
| ------ | -------- | ----------- |
| 1 | `loader.py` | Читает дневные котировки из `txt/` в таблицы pandas, определяет разделитель, парсит даты, фильтрует период |
| 1 | `analytics.py` | Считает доходность каждого календарного месяца, среднее и усечённое среднее по годам, находит лучшие и худшие месяцы |
| 2 | `report.py` | Рисует в PDF сводные таблицы доходностей (по 24 строки на лист) |
| 3 | `report.py` | Рисует по одной странице на каждый месяц каждого активного инструмента: сетка из 6 мини-графиков — по одному на год |

Сборкой этапов управляет `main.py` — точка входа.

## Структура проекта

```
season-months/
├── main.py            # точка входа: этапы 1–3, запуск: python3 main.py
├── config.py          # ВСЕ настройки: период, реестр инструментов, календарь
├── logging_utils.py   # создание папок проекта и помесячный лог
├── loader.py          # этап 1: чтение котировок из txt/
├── analytics.py       # математическое ядро: доходности, средние, экстремумы
├── report.py          # этапы 2–3: отрисовка PDF (таблицы и графики)
├── txt/               # ВХОДНЫЕ данные — дневные котировки (вы кладёте сюда)
├── logs/              # логи запусков (файл на месяц, создаётся автоматически)
└── reports/           # готовые PDF-отчёты (создаётся автоматически)
```

Служебные папки `txt/`, `logs/`, `reports/` создаются автоматически рядом с
`main.py`, поэтому запускать скрипт можно из любого каталога.

## Требования и запуск

- Python 3.10+ (проверено на 3.12)
- pandas 2.x, matplotlib 3.8+ (`pip install pandas matplotlib`)

```bash
cd /Папка проекта
python3 main.py
```

После завершения готовый отчёт появится в `reports/ГГГГ-ММ-ДД-Season-months.pdf`,
а в консоль и лог будут выведены сообщения о ходе работы.

## Конфигурация (config.py)

Все настройки собраны в одном модуле — правится только он, код трогать не нужно.

### `START_FETCH_DATE = "2021-01-01"`

Точка отсчёта анализируемого периода. Фактически данные загружаются **на месяц
раньше** (с 2020-12-01): базой для доходности января 2021 года должно служить
закрытие декабря 2020, а не первая свеча самого января — иначе доходность
первого месяца была бы искажена. Смещение выполняет `loader.load_start()`.

### `TARGET_YEARS = [2021, 2022, 2023, 2024, 2025, 2026]`

Список исторических лет для анализа. Определяет:

- колонки «2021 год … 2026 год» в сводной таблице;
- число мини-графиков на детальной странице (по одному на год, раскладка
  в 2 колонки);
- диапазон лет, по которым считается среднее.

Количество лет может быть любым — сетка страницы перестроится автоматически,
«лишние» пустые ячейки скрываются.

### `TICKERS_CONFIG`

Реестр исследуемых инструментов — список словарей. Каждая запись описывает один
инструмент:

| Поле | Тип | Назначение |
| ------ | ----- | ----------- |
| `ticker` | str | Код инструмента. Одновременно: основа имени файла данных (`SBER-all-d.txt`), ожидаемое имя колонки с ценой в txt-файле, подпись в таблице |
| `market` | str | Секция биржи — справочное поле (`TQBR` — акции/фонды Мосбиржи, `FORTS` — срочный рынок). На расчёты не влияет |
| `name` | str | Человеческое название — заголовок детальной страницы |
| `unit` | str | Единица измерения в подписях изменений: `₽`, `$`, `п.` и т.п. |
| `color` | str | Цвет линий графика и названия тикера в таблице (любое имя цвета matplotlib: `seagreen`, `darkorange`, …) |
| `plot_charts` | bool | `True` — инструмент получает детальные помесячные страницы (этап 3). `False` — только строка в сводной таблице. В таблицу попадают все загруженные инструменты независимо от флага |

Активный набор:

| ticker | name | market | unit | color | plot_charts |
| -------- | ------ | -------- | ------ | ------- | ------------- |
| SBER | Акции Сбербанка (SBER) | TQBR | ₽ | seagreen | **True** |
| GOLD | Фонд ВИМ Золото (GOLD) | TQBR | ₽ | darkorange | False |
| MOEX | Акции Московской биржи (MOEX) | TQBR | ₽ | darkblue | False |
| MTSS | Акции МТС (MTSS) | TQBR | ₽ | DarkTurquoise | False |
| Si | Фьючерс Доллар-Рубль (Si) | FORTS | ₽ | darkgreen | False |
| CR | Фьючерс Юань-Рубль (CR) | FORTS | ₽ | darkgreen | **True** |
| GD | Фьючерс Золото (GD) | FORTS | $ | darkorange | False |
| SV | Фьючерс Серебро (SV) | FORTS | $ | slategray | **True** |
| PT | Фьючерс Платина (PT) | FORTS | $ | chocolate | **True** |
| NG | Фьючерс Природный газ (NG) | FORTS | $ | DarkTurquoise | **True** |

Чтобы добавить инструмент: допишите словарь в `TICKERS_CONFIG` и положите его
txt-файл в `txt/` — больше ничего менять не нужно.

### `MONTHS_RU`

Словарь русских названий месяцев `{1: 'Январь', …, 12: 'Декабрь'}` — используется
в строках таблицы и заголовках страниц.

### `months_order(start_month=None)` и `build_months_to_analyze(start_month=None)`

Вспомогательные функции календаря. `months_order()` возвращает порядок месяцев,
начиная с текущего календарного: в октябре анализ идёт в последовательности
октябрь → ноябрь → декабрь → январь → … → сентябрь. `build_months_to_analyze()`
упаковывает его в список пар `{'number': номер, 'name': название}`. Этот порядок
определяет сортировку строк сводной таблицы и последовательность страниц этапа 3.

## Входные данные (папка txt/)

Для каждого инструмента из `TICKERS_CONFIG` программа ищет файл:

1. `<ticker>-all-d.txt` — полный архив дневных котировок (приоритет);
2. `<ticker>-d-5y.txt` — котировки за несколько лет (запасной вариант).

Требования к содержимому:

- **первая строка** — заголовок с колонками `Date` и `Close` (регистр не важен;
  вместо `Close` подойдёт колонка, названная кодом тикера);
- **разделитель** — табуляция, `;` или запятая, определяется автоматически
  по первой строке файла;
- **даты** — в формате ISO (`2026-10-16`), одна строка — один торговый день;
- прочие колонки игнорируются.

Пример строки данных (запятая): `2026-10-16,301.25`

Если файл инструмента не найден или в нём нет узнаваемых колонок — инструмент
пропускается с предупреждением в логе; если не нашёлся ни один — программа
останавливается с ошибкой.

## Отчёт (reports/ГГГГ-ММ-ДД-Season-months.pdf)

### Сводные таблицы (этап 2)

- Колонки: **Тикер, Месяц, [каждый год из `TARGET_YEARS`], Среднее, Усеч. среднее**.
- Строки сгруппированы по инструментам, месяцы идут в порядке `months_order()`;
  по 24 строки на лист.
- Оформление: чередование фона строк, название тикера — цветом инструмента,
  рост — зелёным, падение — красным, лучшие и худшие месяцы — жирным.
- На последнем листе — примечание о методике усечённого среднего.

### Детальные страницы (этап 3)

По одной странице на каждый месяц каждого инструмента с `plot_charts: True`:

- заголовок «Месяц. Название инструмента»;
- строка «Среднее значение за N лет: +X.XX ₽ (+Y.YY%)» — по всем годам с данными;
- сетка мини-графиков 2 колонки × 3 строки — по одному на каждый год:
  линия цены внутри месяца, начинающаяся с якорной свечи (закрытия предыдущего
  месяца), пунктирные уровни базовой и конечной цены с подписями значений,
  внизу — изменение в деньгах и в процентах.

Пример объёма: 10 инструментов в таблице (5 листов) + 5 инструментов с
`plot_charts: True` × 12 месяцев (60 страниц) = **65 страниц**.

## Логи (logs/)

Файл `logs/ГГГГ-ММ-season-months.log` — по одному на месяц запуска, без ротации.
Каждая запись: `[ГГГГ-ММ-ДД ЧЧ:ММ:СС] сообщение`. В лог дублируется всё, что
выводится в консоль, плюс сообщения без вывода на экран.

## Методика расчётов

- **Доходность месяца** — изменение к закрытию последнего торгового дня
  *предыдущего* месяца: `(закрытие месяца − закрытие прошлого месяца) / закрытие
  прошлого месяца × 100%`. Для самого первого месяца периода (январь 2021)
  базой служит первая свеча самого месяца.
- **Среднее** — среднее арифметическое доходностей месяца по всем годам
  `TARGET_YEARS`, где есть данные. Текущий незавершённый месяц показывается
  в таблице и **участвует в среднем** наравне с завершёнными.
- **Усечённое среднее** — при 3 и более значениях отбрасываются одно минимальное
  и одно максимальное, среднее считается по оставшимся; при 1–2 значениях
  совпадает с обычным средним.
- **Экстремумы** — месяцы с максимальным и минимальным средним (и усечённым
  средним) для каждого инструмента; выделяются жирным в таблице.
- **Нулевая базовая цена** — доходность помечается как н/д (защита от деления
  на ноль, актуально для фьючерсов с отрицательными ценами).
- Дни без торгов (пустой месяц в данных) обозначаются прочерком «—» и в среднее
  не входят.
